## Summary

Shipped **real JWT authentication and per-endpoint role authorization** across the MKT WiFi backend, closing the auth gap that slice 2 explicitly documented as `// TODO(auth-hardening-slice)` and meeting NFR-016 ("role enforcement must be server-side"). The slice extracts a new `backend/auth.py` module (~135 LoC: HS256 JWT mint/verify with python-jose 3.5.0, 5-claim envelope `{sub, name, role, iat, exp}`, 7-day TTL, `UserClaims` dataclass, `verify_token` + `require_role(allowed)` FastAPI dependencies, `get_secret()` with **production fail-fast** posture); a new `backend/auth_routes.py` APIRouter (~60 LoC: real-JWT `/api/auth/login` + stateless `/api/auth/logout`, mirrors slice-1's `portal_routes.py` extraction recipe); and 16 surgical signature edits across `backend/main.py` (5 endpoints get `Depends(verify_token)` for read-all access; 11 get `Depends(require_role([...]))` enforcing `admin` / `admin+viewer` / `admin-only` policies that mirror slice-2's `<RoleGuard>` UX policy with one tightening — `Anunciante` is GET-only on Campaigns since `Campaign.owner_id` doesn't exist yet). On the frontend, ~15 LoC across 3 admin-SPA files: `client.ts` 401 interceptor → `useAuthStore.logout()` + redirect to `/login?reason=expired&next=<path>`; `LoginPage.tsx` reads `?reason=expired` and renders the slice-2-shipped-but-unused `STR.login.expired` notice; both `// TODO(auth-hardening-slice)` markers removed. **115 backend pytest tests pass in 0.45 s** (slice-1's 39 + 76 new) — the 76 new tests cover token mechanics × edge cases, parameterized role × endpoint cells, and JWT_SECRET production fail-fast. **24 frontend vitest tests pass in 0.67 s** (slice-2's 20 + 4 new for the 401 interceptor + the OQ-8 OpenAPI security contract test). **TypeScript strict 0/0**, **Vite build 88.16 KB gzipped initial JS** (+0.02 KB delta from slice-2 baseline — the 401 interceptor cost essentially nothing). **AT-015 PII grep continues to pass; AT-018 confirms no raw token in logs.** Wire-level proof of closure: `curl http://localhost:8000/api/kpis` now returns **HTTP 401** instead of slice-2's 200; with admin JWT it returns 200; with viewer JWT on `/api/monetization` it returns 403. **Zero deferrals — all 20 ATs verified.**

## Lessons Learned

### Process

The 5-phase workflow's compounding payoff peaked in this slice: **slice 3 was the smallest of the three** (~900 LoC vs slice 1's ~3,000 and slice 2's ~3,400) precisely because slices 1 and 2 had pre-wired the surrounding plumbing — the SPA's `Authorization` header was already on every request, the `STR.login.expired` string was already in `strings.ts`, the `<AuthGate>`/`<RoleGuard>` policy was already pinned, the per-endpoint role matrix was already specified in slice-2 prose. /brainstorm spent zero budget rediscovering recipe; /define spent zero budget arguing role policy; /design spent its budget on the **5 OQs that actually had design risk** (HTTPBearer vs OAuth2PasswordBearer, fail-fast posture, `?next=...` preservation, contract test, logger name). Each prior slice paid back compound interest.

- **Pre-design repo inspection is now a habit, not a checklist item.** Slice 1 caught the R13 violation; slice 2 caught the dangling `data.jsx → /api/connection/form` reference + the auth-token gap. Slice 3 caught (a) the `# In production: store hashed passwords in DB and use python-jose for JWTs` comment in `main.py:284` (technical direction was preordained), (b) `EmailStr` would become an orphan import after deleting `LoginRequest`, (c) the `@app.post("/api/auth/login")` and `@app.post("/api/auth/logout")` were the only two routes to extract (no creep). **Lesson: every /design phase begins with `Bash` reading the legacy code; the BRAINSTORM is a spec, not the truth.**
- **OQs with clear "default if unanswered" answers in DEFINE compress /design wall-clock dramatically.** All 8 OQs had defaults written into DEFINE; /design accepted 7 verbatim and only modified OQ-2 (fail-fast) by tightening the trigger condition (`ENVIRONMENT in {"production", "prod"}` rather than just `"production"`). When DEFINE writes good defaults, /design becomes a verification pass, not a deliberation.
- **"Zero existing tests reference legacy login" was a 30-second finding that derisked the migration.** Pre-design `grep -r "LoginRequest\|DEMO_ACCOUNTS" backend/` confirmed: legacy login was only used by the (now-deleted) inline route. The migration could be lossless. **Lesson: deletion-safety is a search problem, not a code problem.**
- **Mid-build verification gates caught both issues before final phase.** Issue 1 (orphan `return {"ok": True}` after deleting the logout body) was caught via `tail -10 main.py` immediately after the Edit. Issue 2 (stale-backend false-positive in the contract test) was caught when running the full vitest suite — fresh-backend reset turned it green. Neither required `/iterate`. Both 1-3 minutes to fix. **The pattern: every Layer's verification gate runs BEFORE the next Layer starts; dependency on local memory is at its highest, fix-cost at its lowest.**
- **DEFINE clarity score above 13/15 stops being interesting.** Slice 3 hit 15/15 — but the "extra" 3 points (above the 12 minimum) didn't change /design's behavior; the work was already crystal clear. **Lesson: don't optimize past 13/15; spend that budget on /design's ADR depth instead.**

### Technical

- **Python-jose 3.5.0 + HS256 + 7-day TTL is the right minimal-but-correct primitive for a single-backend deployment.** No refresh tokens, no `kid` rotation, no `iss/aud/jti` claims. The 5 claims are exactly what the slice needs: `sub` (email-as-identifier), `name` (display), `role` (authz), `iat`/`exp` (TTL). Future slices add `org_id` (multi-tenant) as additive — no contract break. **Lesson: minimum viable JWT envelope = 5 claims for single-tenant; +1 for multi-tenant.**
- **`HTTPBearer(auto_error=False)` over `OAuth2PasswordBearer` was the right OQ-1 call.** `OAuth2PasswordBearer` integrates the login form into Swagger UI but adds a phantom OAuth2 flow we don't have. `HTTPBearer` shows a clean "Authorize" button accepting raw JWT. Operators paste the token from a `curl /api/auth/login` once; Swagger remembers it across requests. `auto_error=False` lets us return our own structured `{"detail": "not_authenticated"}` body with a `WWW-Authenticate` header rather than FastAPI's default `{"detail": "Not authenticated"}` (different capitalization, different shape). **Lesson: when Swagger UX competes with response-shape control, control wins.**
- **The `get_secret()` production fail-fast (OQ-2 / Decision 6) was the most consequential ADR.** Two extra lines of code (`if env in ("production", "prod"): raise RuntimeError(...)`) prevent a class of operational bug where a deployer forgets to set `JWT_SECRET` and the backend silently runs with a random per-process secret that invalidates all tokens on every restart. This is the kind of fail-fast that takes 30 seconds to write and saves 30 minutes of "why is everyone getting logged out every restart?" debugging. **Lesson: in production, refusing to start is more useful than starting wrong.**
- **The 16-endpoint signature edit was tedious but mechanical.** Each endpoint got one new `_: UserClaims = Depends(verify_token)` (or `Depends(require_role([...]))`) parameter. The DESIGN's per-endpoint matrix made it a copy-and-paste exercise: read the matrix row, edit the signature, move on. Slice-3 didn't refactor `main.py`'s structure — it added one parameter per handler. The right level of surgical scope for a security slice. **Lesson: mechanical edits are fine when the rule is unambiguous; refactoring `main.py` was not in scope.**
- **The 8 structured `event_type=auth_*` log events stub the future audit-pipeline slice.** Every authn/authz failure path emits one of: `auth_login_ok`, `auth_login_failed`, `auth_no_token`, `auth_token_expired`, `auth_invalid_token`, `auth_invalid_role`, `auth_missing_claim`, `auth_role_denied`. Future audit-pipeline slice (NFR-015) consumes these via Cloud Logging or Loki without any backend changes. **Lesson: when a future slice has a known consumption pattern, write the producer-side stub now — it costs nothing and reads as readiness.**
- **Per-scope LGPD policy in `grep_pii_check.sh` (slice-2 lesson) held up perfectly through slice 3.** The script's portal-strict + admin-relaxed policies didn't need rewriting — the slice's auth code lives in `backend/auth*.py` (admin scope, where `email` is allowed for `DEMO_ACCOUNTS` lookup), and the `email_prefix: body.email[:3]` log truncation pattern was learned from slice 1's MAC-hash truncation. **Lesson: an auditable policy file expressed as machine-checkable rules is a high-value artifact that compounds across slices.**
- **The wire-level closure proof (`curl` exit codes) is more valuable than test counts.** "115 backend tests pass" is a number; "`curl /api/kpis` returns HTTP 401 instead of 200" is the actual closure of the security gap. The BUILD_REPORT's "What's Different Now" section captured this bookkeeping; the SHIPPED summary preserves it for future security reviewers who need a one-glance proof. **Lesson: every security slice's SHIPPED should include the `curl` proof of before-vs-after.**

### Communication

- **Documenting the auth gap in slice-2's DESIGN paid back here in 0 minutes of context-rebuilding.** Slice-2's "Security Considerations §" + the 2 `// TODO(auth-hardening-slice)` markers + the `Authorization` header pre-wiring told slice-3's brainstorm exactly what to do without ambiguity. /brainstorm could open with "Option B — close Decision 8" and skip the framing question entirely. **Lesson: when shipping a known-incomplete posture, the documentation IS the next slice's brief.**
- **The cumulative DEFINE → DESIGN → BUILD → SHIP archive across 3 slices is now a self-documenting system manual.** A new contributor who reads the 3 SHIPPED files in order learns the platform's history, locked decisions, current state, and explicit gaps in the time it takes to read 3 markdown files. Code archaeology becomes documentation reading. **Lesson: the SHIPPED files ARE the project's `STATE.md`; don't write a separate one.**
- **The BUILD_REPORT's "Issues Encountered & Resolved" table is the most-cited section in the next /brainstorm.** Slice-2's table mentioned "Zustand v5 self-reference cascade" → slice-3's brainstorm cited it as the canonical "library-quirk-of-the-week" that motivates pre-design library smoke tests. Slice-3's table mentions "stale-backend false-positive" → future slices' brainstorms will cite it as evidence that contract tests need fresh-backend isolation. **Lesson: an "Issues" table is not a sign of imperfect work; it's a sign of legible work.**
- **Sample collection in /brainstorm (cuts slice-1's R5 + slice-2's `<EmBreveButton>` + slice-3's `Authorization` header pre-wiring) keeps shipping signal-to-noise high.** Each slice asked the user "do you have any samples that could help ground the solution?" Each time the answer was "yes, here's the prototype HTML / the legacy main.py / the slice-2 SPA." That answer set the recipe; subsequent /design/build inherited a confidence-99% reading of the existing code. **Lesson: never skip the sample-collection question, even on the 3rd slice.**

### Tools & Libraries

- **`python-jose[cryptography]` 3.5.0** — the `[cryptography]` extra pulls in the C-backed `cryptography` library for fast (~2 ms) HS256 sign/verify. The pure-Python `pycryptodome` fallback (no extra) works but is ~3× slower; for an admin panel where each request goes through `verify_token`, the C backend is the right call. Stable since 3.0; well-documented exception types (`ExpiredSignatureError`, `JWTError`).
- **`fastapi.security.HTTPBearer(auto_error=False)`** — the right security primitive for a custom-controlled error response shape. Swagger UI integrates cleanly (lock icon + "Authorize" button); our handler returns structured `{"detail": "..."}` bodies + `WWW-Authenticate` headers without FastAPI's default behavior fighting us.
- **pytest's `monkeypatch` + `caplog`** — the canonical primitives for testing env-var-driven module behavior + log assertion. `test_AT020_random_secret_warning_fires_when_jwt_secret_unset` uses both: `monkeypatch.delenv("JWT_SECRET", raising=False)` + `caplog.at_level("WARNING", logger="auth")` + assertion on `rec.message`. Idiomatic, no hand-rolled monkey-patches, no global fixtures.
- **`pytest.mark.parametrize` stacked twice** — the 57 integration tests come from 5 endpoint families × 3 roles each, with `@pytest.mark.parametrize` decorators stacking to multiply the matrix. Reads cleanly: `@parametrize("method,path", READ_ALL_ENDPOINTS)` + `@parametrize("token_fixture", ["admin_token", "advertiser_token", "viewer_token"])`. Each test name encodes the cell (e.g., `test_AT006_read_all_accepts_all_roles[admin_token-GET-/api/kpis]`); pytest's failure messages point at the exact (endpoint, role) cell that failed.
- **vitest's `vi.spyOn(window, "location", "set")` pattern** — clean way to assert `window.location.href = '/login?...'` redirects. Slice-2's `client.test.ts` patterns carried forward unchanged.
